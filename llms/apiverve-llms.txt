# APIVerve Documentation

> APIVerve publishes 367 ready-to-call APIs behind one key and one response shape. Every API answers with the same three top-level keys (`status`, `error`, `data`), authenticates with an `x-api-key` header, and is billed per call.

Markdown source for the guide pages below is available at the same path under https://docs.apiverve.com/md/, e.g. `/md/quickstart.md`.

Reference pages have no /md/ mirror of their own: each one canonicalises to its APIVerve catalog page, and it is that page which carries the markdown mirror worth quoting. Both are linked per entry below.

## Start

- [Quickstart](https://docs.apiverve.com/quickstart): Get a working API call in about four minutes. The same request shape works on every endpoint in the catalog.
- [Authentication](https://docs.apiverve.com/authentication): One key for your whole account. Where it lives, how to connect it, what a rejection looks like, and how to rotate without downtime.
- [Key scoping](https://docs.apiverve.com/authentication/key-scoping): Restrict what a key can reach — blocked endpoints, blocked VerveKit tools, IP allow-lists and per-key rate limits — and what each restriction returns when it fires.
- [Sub-keys](https://docs.apiverve.com/authentication/sub-keys): Scoped credentials for a client, an environment or a job — how they bill, how they rate-limit, and why one key per consumer beats one key everywhere.
- [Key rotation](https://docs.apiverve.com/authentication/key-rotation): Replacing your key — what happens the instant you rotate, how to do it without an outage, and what to do when a key has leaked.
- [Key expiration](https://docs.apiverve.com/authentication/key-expiration): Give a key an end date so it retires itself — the available durations, what an expired key returns, and where an expiry helps rather than hurts.
- [Making requests](https://docs.apiverve.com/making-requests): Query parameters, JSON bodies, file uploads, timeouts and concurrency — everything that works the same way on every endpoint.
- [Rate limits](https://docs.apiverve.com/rate-limits): Per-plan request ceilings, the headers that report them, and how to back off correctly — including the two very different failures that both answer 429.
- [Security](https://docs.apiverve.com/security): Where to keep a key, how to bound what it can do, what the transport guarantees, and what to check before you ship.

## Guides

- [Hide your API key behind a proxy](https://docs.apiverve.com/guides/hide-your-api-key): A key in front-end code is readable by everyone who loads the page. Two working proxies — Cloudflare Workers and Vercel Edge — plus what to do when the key genuinely has to be public.
- [Migrations](https://docs.apiverve.com/migrations): Moving an existing integration onto APIVerve — the order to do it in, what actually changes in your code, and how to cut over without a flag day.
- [Migrating from RapidAPI](https://docs.apiverve.com/migrations/rapidapi): Replacing per-API hosts, keys and subscriptions with one host and one key — the code changes, the mapping problem, and cutting over safely.
- [FAQ](https://docs.apiverve.com/faq): Straight answers to the questions we actually get asked — keys, credits, limits, billing and the things that commonly go wrong.
- [Glossary](https://docs.apiverve.com/glossary): The terms used across these docs — general vocabulary, and the words that mean something specific here.

- [Embedded forms](https://docs.apiverve.com/vervekit/forms): Drop a working form for any endpoint onto your site with two lines of HTML — no backend, no key in the browser.
- [Postman collection](https://docs.apiverve.com/postman): The whole catalog as a Postman collection — folders per category, one variable to set, and a mock mode that costs nothing.
- [APIVerve Studio](https://docs.apiverve.com/studio): The desktop API client — what it does, how it differs from the browser playground, and where your requests are stored.
